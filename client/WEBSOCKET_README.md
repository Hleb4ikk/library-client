# WebSocket Integration для реалтайм обновления лайков

## Что реализовано

✅ **Задача 1**: Подключение к WebSocket при входе на страницу деталей книги  
✅ **Задача 2**: Присоединение к комнате `book:{olid}`  
✅ **Задача 3**: Обработка события `likes:updated` — обновление счётчика без перезагрузки  
✅ **Задача 4**: Отключение при уходе со страницы (cleanup)  
✅ **Задача 5**: Fallback: если WS недоступен — показывать актуальное число при загрузке

## Архитектура

### 1. WebSocket Сервис (`src/services/socket.service.ts`)

Singleton класс для управления WebSocket соединением:

- **Методы**:
  - `connect()` — подключение к серверу
  - `disconnect()` — отключение
  - `joinBookRoom(bookOlid)` — присоединение к комнате книги
  - `leaveBookRoom(bookOlid)` — покидание комнаты
  - `on(handlers)` — регистрация обработчиков событий
  - `isConnected()` — проверка статуса подключения

- **События**:
  - `connect` — успешное подключение
  - `disconnect` — отключение
  - `connect_error` — ошибка подключения
  - `likes:updated` — обновление лайков

- **Особенности**:
  - Автоматическое переподключение (до 5 попыток)
  - Поддержка websocket и polling транспортов
  - Подробное логирование для отладки

### 2. API функции (`src/features/books/api/books.api.ts`)

Добавлены новые функции:

```typescript
// Получение деталей книги
getBookDetails(olid: string): Promise<ApiSuccessResponse<BookDetailsResponse>>

// Переключение лайка
toggleBookLike(olid: string): Promise<ApiSuccessResponse<ToggleLikeResponse>>
```

### 3. Страница деталей книги (`src/pages/book-details-page.tsx`)

**Обновления**:

- Загрузка реальных данных книги через API при монтировании
- WebSocket подключение с присоединением к комнате `book:{bookId}`
- Обработка события `likes:updated` с обновлением состояния
- Cleanup: покидание комнаты при размонтировании
- Оптимистичное обновление UI с откатом при ошибке
- Индикатор WebSocket статуса (зеленый/красный кружок)

## Как тестировать

### Подготовка

1. **Запустить backend сервер**:
   ```bash
   cd ../server
   npm run dev
   ```
   Сервер должен запуститься на порту 8080

2. **Запустить frontend**:
   ```bash
   npm run dev
   ```
   Приложение откроется на http://localhost:5173

3. **Авторизоваться** (необходимо для лайков):
   - Перейти на `/auth`
   - Зарегистрироваться или войти

### Тест 1: Подключение к WebSocket

1. Открыть DevTools → Console
2. Перейти на страницу любой книги (например `/books/OL123W`)
3. В консоли должны появиться логи:
   ```
   [WS] Подключение к http://localhost:8080...
   [WS] Подключено успешно <socket-id>
   [BookDetailsPage] WebSocket подключен
   [WS] Присоединение к комнате: book:OL123W
   ```
4. В правом верхнем углу страницы должен появиться зеленый индикатор "WS подключен"

### Тест 2: Реалтайм обновление лайков

**Вариант A: Два браузера**

1. Открыть страницу книги в двух разных браузерах (или окнах инкогнито)
2. Авторизоваться в обоих
3. В первом браузере нажать кнопку "♡ Нравится"
4. **Ожидаемый результат**: счетчик лайков обновится **в обоих браузерах** без перезагрузки

**Вариант B: Консоль браузера**

1. Открыть страницу книги
2. В консоли DevTools выполнить:
   ```javascript
   // Симулировать входящее событие
   window.dispatchEvent(new CustomEvent('socket-test'))
   ```

### Тест 3: Обработка events

1. Поставить/убрать лайк
2. В консоли должны появиться логи:
   ```
   [BookDetailsPage] Лайк переключен: true, новое количество: 5
   [WS Broadcast] Отправлено обновление лайков в комнату book:OL123W: count = 5
   [BookDetailsPage] Получено обновление лайков для OL123W: 5
   ```

### Тест 4: Cleanup при уходе со страницы

1. Находясь на странице книги, перейти на главную
2. В консоли должны появиться логи:
   ```
   [BookDetailsPage] Cleanup для книги: OL123W
   [WS] Покидание комнаты: book:OL123W
   ```
3. Сокет остается подключенным (для переиспользования)

### Тест 5: Fallback механизм

**Сценарий A: Backend недоступен**

1. Остановить backend сервер
2. Перезагрузить страницу книги
3. **Ожидаемый результат**: 
   - Показывается ошибка загрузки
   - Отображаются mock данные книги
   - Индикатор WebSocket красный "WS отключен"

**Сценарий B: Backend доступен, WebSocket недоступен**

1. Backend работает нормально
2. **Ожидаемый результат**:
   - Данные книги загружаются из API
   - Лайки работают через HTTP API
   - Реалтайм обновления недоступны

## Логи для отладки

Все ключевые действия логируются с префиксом:

- `[WS]` — WebSocket сервис
- `[BookDetailsPage]` — страница деталей книги
- `[WS Broadcast]` — broadcast с сервера (в логах backend)

## Backend WebSocket API

Сервер уже настроен и поддерживает:

**События от клиента**:
- `join_book_channel(olid: string)` — присоединиться к комнате книги
- `leave_book_channel(olid: string)` — покинуть комнату книги

**События от сервера**:
- `likes:updated` — обновление лайков
  ```typescript
  {
    book_olid: string,
    count: number
  }
  ```

**Комнаты**: `book:{olid}` (например, `book:OL123W`)

## Конфигурация

WebSocket сервер автоматически определяется из `VITE_API_URL`:

```env
# .env
VITE_API_URL=http://localhost:3000/api
```

Из этого извлекается базовый URL: `http://localhost:3000`

## Возможные проблемы

### WebSocket не подключается

1. Проверить, что backend запущен на порту 8080
2. Проверить CORS настройки на backend
3. Открыть DevTools → Network → WS и проверить подключение

### Лайки не обновляются в реальном времени

1. Проверить, что индикатор WebSocket зеленый
2. Проверить в консоли логи `[WS Broadcast]` на backend
3. Убедиться, что оба клиента в одной комнате

### Ошибка "Не удалось подключиться к серверу"

1. Backend не запущен или недоступен
2. Неправильный URL в `.env` файле
3. Проблемы с сетью
